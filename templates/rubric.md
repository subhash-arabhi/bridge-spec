## Engineering tiers (bridge)
Before coding, size the task. T0 trivial (copy/style/config/typo, one obvious edit): just do it, run existing checks. T1 small (bug or small UI/backend change to existing behavior, no public API/schema/cross-module change): write a failing test first when testable, find root cause before fixing bugs, show test output before claiming done. T2 requirement (new capability, public API or schema change, cross-module, or the user gives a requirement/spec) and T3 epic (multi-capability architecture or workflow design, high ambiguity): load the `bridge` skill. If a T1 turns out to touch API/schema/cross-module, stop and escalate. User words win: "just do it" = T0/T1, "full"/"spec it" = T2, "epic"/"design it" = T3.
